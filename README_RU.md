## 🦀 Native Voice Engine (Rust Powered)
Основная логика обработки голосового трафика вынесена в нативный модуль на **Rust** (`rs`). Критические операции выполняются независимо от основного event loop Node.js, что позволяет голосовому движку продолжать работу даже при высокой нагрузке на основной поток.

* **Голосовой движок** — собственная реализация обработки Discord Voice: `UDP` + `SRTP` + `Opus`.
* **Безопасность** — поддержка **End-to-End Encryption (E2EE 🔐)** через протокол **Discord DAVE**.
* **Тайминг и планировщик** — нативная циклическая система с точным таймингом и автоматическим распределением нагрузки между активными голосовыми сессиями.
* **Opus** — обработка и передача Opus-фреймов без необходимости использования внешнего Opus-кодировщика на этапе отправки.
* **FFmpeg Integration** — используется для декодирования аудио, преобразования потока и применения сложных аудиофильтров. Порядок применения фильтров может влиять на итоговый результат.

## 🌐 Платформы и парсинг

Поддерживается работа с **YouTube**, **Spotify**, **VK**, **Yandex Music**, **SoundCloud**, **Deezer** и **Apple Music** *(в разработке)*.

* **Умный Fallback** — если трек недоступен на одной платформе, система может автоматически найти альтернативный источник на другой.
* **Related Tracks** — автоматический поиск и добавление похожих треков для продолжения воспроизведения.
* **Worker Threads** — ресурсоёмкие операции поиска и парсинга выполняются в отдельных worker-потоках, не блокируя основной поток Node.js.
* **Расширяемость** — модульная архитектура на основе `Dynamic Handler` позволяет добавлять новые платформы без изменения основной логики плеера.

## 🎖️ Устойчивость к блокировке Event Loop
Голосовой движок работает в нативном Rust-модуле и не зависит от event loop Node.js для выполнения критического цикла обработки и отправки аудио.

Даже при существенной нагрузке или временной блокировке основного потока Node.js уже запущенное воспроизведение продолжает обрабатываться нативным голосовым движком.

Это позволяет отделить **управляющую логику Node.js** от **критического аудиопайплайна**, минимизируя влияние задержек event loop на стабильность воспроизведения.

## 🎵 [`Качество звука`](https://youtu.be/SwmPmEEDI58)

* **Без искусственных ограничений битрейта** — аудио пайплайн не ограничивает битрейт исходного материала. Теоретически можно передать поток с битрейтом выше стандартных возможностей Discord, однако фактическое качество ограничивается самим Discord и используемым аудиокодеком.
* **Hot Audio Swap** — мгновенное и бесшовное переключение между аудиопотоками без заметных разрывов между треками.
* **Audio Effects** — плавный `fade-in` / `fade-out` при переключении треков и выполнении действий `skip`, `seek` и `pause`.
* **Аудио фильтры** — более 16 встроенных аудио фильтров с возможностью легко добавлять собственные через JSON-конфигурацию [`filters.json`](src/core/player/filters.json).
* **Синхронизация** — точная синхронизация аудиопотока и его обработки без дополнительных искажений, возникающих из-за самого механизма переключения и применения фильтров.

> [!WARNING]
> WatKLOK не может гарантировать отсутствие потерь пакетов после отправки аудиоданных в Discord.
>
> Потери могут возникать на любом участке сетевого соединения между ботом, серверами Discord и клиентом. При нестабильном интернет-соединении клиента это может приводить к пропускам или восстановлению потерянных фреймов средствами Opus.
>
> Полностью исключить потерю пакетов невозможно из-за особенностей UDP и сетевой инфраструктуры Discord. При этом потери, возникающие непосредственно в аудиопайплайне бота, не должны маскироваться под сетевые проблемы — состояние воспроизведения отображается в сообщении текущего трека.

## 🎛 Интерфейс

* **Интерактивное управление** — доступные кнопки и действия автоматически изменяются в зависимости от текущего состояния плеера.
* **Прогресс-бар** — отображает текущее положение трека и тайм-коды воспроизведения.
* **Отзывчивый интерфейс** — основные действия доступны непосредственно из плеера и не требуют повторного ввода команд.
* **Управление очередью** — просмотр, удаление и пропуск треков доступны непосредственно из интерфейса.
* **Управление воспроизведением** — поддерживаются повтор, перемотка, изменение громкости и применение аудиофильтров.

## 🚀 Запуск
### Требования
Для запуска необходимы:
* **Node.js**
* **FFmpeg**
* **Rust** — только если требуется самостоятельно собрать native-компоненты
> Собирать Rust-компоненты самостоятельно **не обязательно**. Готовые native-сборки доступны в [GitHub Actions](https://github.com/SNIPPIK/UnTitles/actions/workflows/build.yml).

### Установка
```shell
# Клонируем репозиторий
git clone https://github.com/SNIPPIK/UnTitles
cd UnTitles

# Устанавливаем зависимости
npm install

# Настраиваем окружение
cp .env.custom .env
```
> Все необходимые параметры уже должны быть указаны в `.env.custom`. Перед запуском достаточно скопировать и указать токен в `.env` и при необходимости изменить значения.

### Сборка native-компонентов
Если Rust установлен и native-компоненты необходимо собрать самостоятельно:
```shell
npm run build:native
```
Если собирать Rust-компоненты не требуется, можно использовать готовую сборку из [GitHub Actions](https://github.com/SNIPPIK/UnTitles/actions/workflows/build.yml). Полученные native-модули необходимо разместить в:
```text
build/native
```

### Сборка и запуск
После установки зависимостей и подготовки native-компонентов:
```shell
# Сборка TypeScript
npm run build

# Запуск
npm run start
```

Или одной командой:
```shell
npm run build && npm run start
```
